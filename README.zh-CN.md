# Daybreak DamageTracker

[English](README.md) · [Steam 创意工坊](https://steamcommunity.com/sharedfiles/filedetails/?id=3776927292) · [GPL-3.0-only 许可证](LICENSE)

Daybreak DamageTracker 是一个面向 Terraria 1.4.4 / tModLoader 多人游戏的服务端统一控制型 Boss 伤害结算模组。它统计服务端实际接受的有效伤害、展示团队排名，并把每位玩家的详细伤害来源限制为仅本人可见。

此分支是 **0.2.1 测试候选**；源码更新不代表创意工坊已经发布。网络格式要求服务器与所有客户端
使用相同版本，正式部署前须完成 [针对性验收](TESTING.md#021-focused-acceptance)。

## 主要功能

- 从发现 Boss 开始跟踪战斗，支持胜利、失败、逃离和管理员手动结算。
- 每个 Boss 都有独立的团队总伤害、本体伤害、战斗时长、玩家排名、占比和本人来源树。
- 同时多 Boss 时，每只 Boss 一结束就单独结算，不需要等待仍在场的其他 Boss。
- 显示每场胜利的最后一击归属：直接命中者，或致死持续伤害跳中份额最大的玩家；无法归属的击杀不显示该行。
- 按武器、饰品、武器本体和弹幕类型整理本人的伤害来源。
- 按实际生命扣除统计持续伤害，并在本人来源树中显示可归属的原版减益。
- 来源和弹幕分支可以彼此独立地展开或折叠；展开一件武器不会收起另一件武器的
  弹幕列表，长面板会限制在当前视口内并支持滚轮浏览。
- 每个客户端可保留最近 1–10 只 Boss 的记录：最新一场用 `/dt`，之后按需使用 `/dt1` 至 `/dt9`。
- 每个客户端可把自动弹出面板的持续时间设为 1–120 秒；`/dt` 手动打开的面板会一直保留到主动关闭。
- 面板已打开时，后续结算会追加到同一滚动面板下方。
- 可选集成 Boss Checklist，并为普通 Boss 提供 `npc.boss` 回退识别。
- Boss Checklist 漏列但通过 `realLife` 连接到已登记控制体的 Body/Tail 会归入同一场，
  不会另外生成重复结算。
- Boss 通过 tModLoader 父级来源生成的护盾、召唤物和战斗内幻象会在归属唯一时进入该
  Boss 的团队伤害与排名，但不进入 Boss 本体小计。归属绑定到具体 NPC 实例，同类型的
  无关目标和独立召唤的同类 Boss 仍保持分开；歧义目标不猜测。
- 服务端可为特殊转阶段 Boss 配置生命周期覆盖项。
- 团灭或脱战后会拆分无关 Boss，同时保留真正同时出现的多个 Boss 和已配置的车轮战。
- 一只击杀、一只脱战时会分别及时弹出“胜利”和“逃离”，不会互相阻塞。
- 玩家断线重连后，公开排行榜会合并为一行，但私有来源仍只按精确连接投递。
- 支持的 Boss 名称会按每个客户端选择的语言独立解析。

## 隐私边界

公开结算只包含团队排名。详细伤害来源由玩家自己的客户端记录，不会写入公开结算包或历史包。服务端确认的弹幕来源与持续伤害来源增量也只会发送给对应玩家本人。

展示项、行数和结算接收范围由服务端统一控制，客户端没有对应的重复开关。客户端偏好只控制
自动弹出、自动面板持续 1–120 秒、保留 1–10 场本地记录、面板深色底色透明度（默认 `0.90`），
以及服务端已经授权项目的排列顺序，不能改变服务端展示策略或扩大数据权限。

## 安装

可以直接订阅 [Steam 创意工坊条目](https://steamcommunity.com/sharedfiles/filedetails/?id=3776927292)，也可以手动把同一个 `DaybreakDamageTracker.tmod` 安装到专用服务器和所有客户端。网络数据格式可能随版本调整，因此服务端与客户端不能混用不同版本。

模组配置菜单会分别显示“客户端设置”和“服务端设置”。首次加载后，tModLoader 会创建：

```text
<tModLoader SavePath>/ModConfigs/DaybreakDamageTracker_ServerConfig.json
```

0.2.0 会在新文件不存在时一次性导入旧的 `DaybreakDamageTracker.Server.json`，并保留旧文件
作为回滚参考。房主可直接修改服务端设置；独立服务器上的远程客户端默认只能查看，需由服务端
控制台临时授权当前连接，断线后授权自动失效。

两张设置页都使用实际结算渲染器提供可交互、可独立滚动的实时面板预览。服务端只决定内容许可、行数上限、接收范围和
Boss 生命周期；是否自动弹出、自动面板持续时间、历史数量、底色透明度与已授权内容的排列顺序
只属于客户端。每个选项会明确标出默认值，两张页面也各自提供需要二次确认且仍需保存的“全部恢复
默认值”。

全部配置项和特殊 Boss 适配方法见 [SERVER_CONFIG.md](SERVER_CONFIG.md)。

## 命令

客户端聊天命令：

```text
/dt
/dt1
/dt2 ... /dt9
/dt list
/dt chat
/dt close
```

历史指令使用相对位置：`/dt` 是最新一场，`/dt1` 是上一场，之后依次类推；设置保留几场，就有几条记录可用。新结算会让旧记录顺延，因此聊天栏会用一条极简消息重列当前的“Boss 名称｜结算状态｜查看指令”，不再添加 `#0` 一类编号。

专用服务器控制台命令：

```text
dtserver reload
dtserver status
dtserver config grant <玩家槽位>
dtserver config revoke <玩家槽位>
dtserver config clear
dtserver finish victory|defeat|escaped|manual
```

## 从源码构建

需要 .NET 8 SDK 和 tModLoader 1.4.4。最简单的方法是把仓库克隆到 tModLoader 的 `ModSources` 目录；项目会自动使用父目录中的 `tModLoader.targets`。

如果源码位于其他位置，请显式传入 tModLoader 的构建目标文件：

```powershell
dotnet build -c Release -p:TModLoaderTargets="D:\Steam\steamapps\common\tModLoader\tMLMod.targets"
```

只验证编译而不打包或安装 `.tmod` 时，可增加 `-p:BuildMod=false`。

## 已知边界

Terraria 1.4.4 仍会接受客户端提交的命中伤害值。本模组按服务端 `NPC.StrikeNPC` 的返回值归属伤害，但它不是反作弊系统。直击伤害因此与游戏内飘字、原版 DPS 计量饰品采用同一口径：最后一击可能包含超过目标剩余生命的溢出伤害；持续伤害由游戏分块扣血，始终按实际扣除的生命统计。

普通物品/弹幕命中，以及 Terraria 持续伤害更新实际扣除的生命都属于支持范围。中毒、着火、诅咒狱火、霜火、酸性毒液、暗影焰、狱炎、霜冻和灵魂汲取会在施加路径能确认玩家时保留归属；骨制标枪、触手钉刺、血腥屠刀、破晓之光和星尘细胞的叠加持续伤害会通过仍附着在目标身上的弹幕实例确认玩家与来源。刷新同一种减益只取得新增的持续时间，不会抢走原本剩余时间。多个受支持效果同时存在时，会按原版生命恢复权重拆分该次真实扣血，同时严格保持总数不变；最终负生命恢复中超过已知效果权重的部分会保留为未归属，不会被塞给已知效果。

DoT 团队总量按实际扣血记录，但其他模组改变效果强度时，玩家之间的份额只是原版权重估计。灾厄的弱点、抗性、蠕虫减伤及混合未知效果都会改变真实比例；只有最终负生命恢复超过已知权重总和的部分，才能单列为“未归属持续/服务端伤害”，同时发生的缩放可能让未知份额无法被单独分离。无法识别施加者的效果自身保持未归属。此类修正下，DoT 玩家占比和按最大份额选择的最后一击归属均不应视为精确测量。

减益提前移除后再次施加会清除旧归属，即使新施加者无法识别，也不会继承旧玩家的份额。其他模组在持续伤害更新之外直接修改 `npc.life`，仍没有通用捕获路径。

普通重复挑战中的分段 Boss 会按根/控制 NPC 跟踪。本体列表和生命周期控制体列表彼此独立，
Body/Tail 的生成或直接清理不会冒充未完整结算的控制体。控制器触发 `OnKill` 后，只有没有
兄弟控制器或转阶段后继控制器接替，才会确认最终结束；最终 Body/Tail 清理不要求每一节都
触发 `OnKill`。Boss Checklist 漏列但通过 `realLife` 指向该控制器的 Boss 标记体节，也会
自动并入同一场。具有无 NPC 演出阶段或非常规最终形态的 Boss 仍可能需要服务端覆盖配置；
默认关闭通用的无 NPC 超时，以免在转阶段时提前结算。

某些阶段会在同一次权威扫描中短暂同时出现旧控制体和后继控制体。只有在短同步窗内旧控制体
完整退出，且所有存活根都属于刚出现的后继集合时才接受交接；稳定多控制体战中仅一只逃跑
不会被这种兼容规则掩盖。

灾厄兼容会在 Boss Rush 中改用控制体击杀确认，并识别天顶世界荒漠灾虫转为渊海灾虫的
特殊流程，但只有权威 NPC 父级来源明确证明转场时才会合并；单纯同场仍分别结算。该兼容
基于灾厄 2.2.4 的程序级复核；未来灾厄版本或没有提供标准父级生成来源、
Boss Checklist、`realLife`、`OnKill`/downed 信号的自定义实现仍可能需要服务端覆盖配置。

同一时刻出现、且被上游登记为完全相同 Boss key 的多个实例无法在通用层可靠区分为
“重复召唤”还是合法双体、分裂控制体或阶段接替，因此会合并进同一个账本。不同 key 的
同时 Boss 仍会独立统计；若要拆分相同 key 的并行实例，需要对应模组提供实例分组与阶段
交接信号，或增加专用适配器。

不同轮次使用不同 Boss Checklist key 的车轮战，可以通过相同的 `EncounterGroupKey` 归为一场。若该车轮战允许全员阵亡后复活继续，还可启用 `ContinueAfterPartyWipe`，并应配置可靠的最终 NPC。
